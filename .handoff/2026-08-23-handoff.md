## 一、项目概况

本项目是一个 **纯 Markdown Prompt Skill**，目标是将故事/脚本/创意转换为具有导演意图、空间连续性、动作逻辑和可视化注释的故事板方案，并编译为图像/视频模型可执行 Prompt。

项目从 `storyboard-video-previs` fork 演进，当前阶段为 **V1 第一版规则层建设**。

### 技术栈

- 纯 Markdown 规则文件，无代码执行器、JSON Schema 或自动化测试框架
- 图像生成依赖 Codex 内置 imagegen 能力
- Git 管理，本地 Markdown Issue 追踪（`.scratch/`）

### 产品定位

> Universal Storyboard Director：将故事、脚本、创意、角色、场景与参考图，转换为具有导演意图、空间连续性、动作逻辑和可视化注释的故事板方案，并编译为图像/视频模型可执行 Prompt。

## 四、当前正在进行的工作

### Phase 20：Soft Validator Policy（in_progress → 被中断）

用户确认的 Validator 策略：

**硬校验（BLOCKER）只覆盖以下情况：**
- 用户明确要求的画幅、Panel 数、布局完全不符
- 主模式明显错误（如 Horror 被生成成 Action）
- 用户指定的关键角色、道具或场景缺失
- 关键连续性无法解释的错误（人物瞬移、核心道具消失）
- Prompt 存在明显互相矛盾（"黑白分镜"同时要求"全彩成片"）
- 输出缺少基本必需部分（没有 Panel 表或整合 Prompt）

**其余全部降级为 WARNING/NOTE：**
- 镜头类型重复、动作因果不够强、Wide Reset 不够理想、Motion DNA 不够稳定、结尾不够有冲击力、Panel 子画面拆分等

**明确不强制：**
- 每格必须有动作、每种景别必须出现、每任务必须完整 Continuity、每 Action 必须完整动作阶段等

## 六、已确认的设计决策

| 决策 | 内容 |
|---|---|
| V1 范围 | Core Architecture + Mode Router + Narrative + Action Previs |
| 项目形态 | 纯 Markdown Skill，不引入代码执行器或 JSON Schema |
| 内部模型 | Project → Sequence → Scene → Shot → Panel（不直接暴露给用户） |
| 默认输出 | Brief + Panel Table + Prompt + Validation |
| Continuity 策略 | Action 强制 FULL，Dialogue/Horror 使用 LIGHT，Keyframe 使用 MINIMAL |
| Annotation Profile | 普通任务 SIMPLE，动作/舞蹈 PRO，关键帧/广告 CLEAN，兼容旧 Prompt 时 LEGACY_BLUE |
| 面板布局 | 8/12/16/24 默认；20 面板仅 Action Previs 专用 |
| Golden Case | 动作（Whoking）、对白（厨房录音笔）、恐怖（无人走廊） |
| Validator | 宽松策略：基础硬校验 + 专业软校验，不因审美或质量不足阻断交付 |
| 用例校验 | 推迟到 V2 完成后统一回归 |
