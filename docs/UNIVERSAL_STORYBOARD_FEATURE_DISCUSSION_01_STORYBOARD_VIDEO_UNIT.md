# Universal Storyboard Director — 功能探讨记录 01

## 故事板单元、分段剧本与完整视频提示词

> 文档性质：**功能探讨与共识记录，不是正式设计文档**  
> 记录时间：2026-08-23  
> 当前状态：概念已基本达成共识，暂不进入实现  
> 适用范围：长视频拆分、故事板单元、视频生成提示词、音频设计与段落衔接

---

## 1. 讨论背景

当用户要制作一个较长的视频，例如 120 秒视频时，不适合只生成一张完整故事板。更实际的生产方式是将视频拆分为多个完整片段：

```text
120 秒视频
→ 故事板单元 A：00–10 秒
→ 故事板单元 B：10–20 秒
→ 故事板单元 C：20–30 秒
→ ……
```

默认每个片段为 10 秒；在需要更完整的动作、停顿或情绪展开时，也支持 15 秒片段，但 15 秒生成速度更慢。

本次讨论确认：故事板不应只是静态图片，还应成为一个可以继续生成视频和音频的完整生产单元。

---

## 2. 当前已确认的核心抽象

推荐使用“**故事板单元（Storyboard Unit）**”作为长视频拆分后的基本工作单元。

一个故事板单元对应一个完整的视频片段，并包含该片段所需的叙事、视觉、视频和音频信息：

```text
项目总剧本
  └── 故事板单元 A（00–10 秒）
        ├── 段落简介 / 分段剧本
        ├── 故事板生成提示词
        ├── 故事板面板规划
        ├── 音频设计
        ├── 视频生成提示词
        └── 与前后单元的衔接信息
```

因此，生产关系不再只是：

```text
故事板 A → 视频提示词 A
```

而是：

```text
故事板单元 A
  → 故事板 A
  → 视频提示词 A
  → 音频设计 A
  → A 到 B 的连续性衔接
```

---

## 3. 故事板单元与完整剧本的关系

每个故事板单元需要有与剧本相关的简介或分段剧本，但不应重复保存完整总剧本。

### 3.1 总剧本

总剧本负责全片层面的内容：

- 故事主题和整体冲突
- 角色身份、关系和长期变化
- 世界观、场景和全局视觉风格
- 全片节奏和结构
- 不允许在各段落之间改变的连续性事实

### 3.2 分段剧本 / 段落简介

每个故事板单元只记录当前片段相关的叙事信息：

```text
Segment ID: SEG-004
时间：30–40 秒
叙事目的：角色第一次发现设备异常，并决定开始修复
前置状态：设备损坏，角色尚未意识到危险
本段事件：发现裂缝 → 警报响起 → 拿起工具 → 做出修复决定
后置状态：核心被固定，但危险开始加剧
情绪曲线：平静 → 警觉 → 紧张
对白 / 音效：警报声、呼吸声，无对白
衔接输入：承接上一段的设备损坏状态
衔接输出：进入下一段的正式装配过程
```

分段剧本的作用是让故事板和视频提示词知道“这一段为什么存在”，而不是只描述画面表面发生了什么。

---

## 4. 故事板单元的建议组成

一个单元可以最终以一个合并文件呈现，但内部应保持分区清晰：

```text
# Storyboard Unit A

## Segment Brief
## Script Beats
## Storyboard Prompt
## Storyboard Plan
## Audio Design
## Final Video Prompt
## Continuity In
## Continuity Out
```

各部分职责如下：

| 部分 | 作用 |
|---|---|
| Segment Brief | 说明本段时间范围、叙事目的和主要变化 |
| Script Beats | 记录本段的动作、对白、情绪和因果节拍 |
| Storyboard Prompt | 用于生成该片段的故事板图 |
| Storyboard Plan | 说明 Panel、镜头、构图和节奏 |
| Audio Design | 规划对白、环境声、音效、音乐和静默 |
| Final Video Prompt | 将视觉、动作、镜头、连续性和音频整合成一个完整视频提示词 |
| Continuity In | 说明本段从上一段继承的状态 |
| Continuity Out | 说明本段结束后交给下一段的状态 |

---

## 5. 相邻故事板之间的衔接方式

通常不需要额外增加一张独立的“衔接故事板”。推荐采用两个相邻单元之间的 **Continuity Handoff（衔接契约）**。

```text
故事板 A 的最后状态
        ↓
故事板 B 的开始状态
```

A 的末镜头和 B 的首镜头不需要完全重复，但必须共享关键视觉事实：

- 角色位置、姿态和运动方向
- 道具位置与状态
- 场景空间锚点
- 摄影机方向和轴线
- 光线、时间和环境状态
- 动作是否处于未完成状态
- 情绪和叙事目的

例如：

```text
A 末镜头：角色推开仓库门，门内出现强光
B 首镜头：从同一扇门、同一方向、同一角色状态继续进入强光
```

### 5.1 什么时候需要单独的过渡镜头

只有在下列情况下，才建议增加专门的过渡镜头或过渡单元：

- 发生明确的时间跳跃
- 发生场景切换
- 角色或道具状态发生重大变化
- 需要视觉匹配、蒙太奇或特殊转场
- 上一段的结尾无法自然成为下一段的开头
- 视频模型容易丢失角色身份、空间方向或关键道具

正常情况下优先使用：

```text
A 末镜头 → B 首镜头
```

而不是默认增加：

```text
A 末镜头 → 衔接故事板 → B 首镜头
```

## 6. 一个故事板单元对应一个完整视频提示词

在当前确认的生产方式中：

```text
一个 10 秒故事板单元 → 一个完整视频提示词
一个 15 秒故事板单元 → 一个完整视频提示词
```

该视频提示词应是内容丰富、时间顺序明确、包含音频设计的长提示词，而不是只描述一个静态画面。

不过，“长”不等于无结构地堆叠形容词。推荐使用带标题区块的结构化长提示词。

---

## 7. 完整视频提示词的建议结构

### 7.1 片段基本契约

```text
Segment ID
Duration
Aspect Ratio
Primary Mode
Video Type
Primary Visual Source
Reference Inputs
Output Intent
Frame Rate / Motion Cadence
Audio Capability Assumptions
```

这里不把 `Generation Mode` 写死为某一种生成方式。视频提示词 Agent 应根据用户提供的是故事板图、首帧、尾帧、角色参考、场景参考、纯文本需求还是其他素材，自适应判断最合适的提示词组织方式，并在必要时说明所依赖的参考输入。

当任务明确基于故事板生成视频时，`Primary Visual Source` 应标记为 `STORYBOARD`。Agent 必须先分析故事板的 Panel 顺序、构图、景别、角色姿态、道具状态、空间关系和镜头变化，再生成视频中的运动与声音描述。故事板不是最终提示词的装饰性参考，而是本段视频的核心视觉素材。

`Output Intent` 用于说明本段是连续长镜头、内部包含多次剪切、时间压缩蒙太奇，还是需要稳定尾帧的可拼接片段。`Frame Rate / Motion Cadence` 不强制指定具体数值时，也可以描述为电影感、平滑、克制、快速或逐格感等运动节奏。

### 7.2 全局连续性锁定

记录本段不可随意改变的事实：

- 角色外貌、服装和身体状态
- 场景、空间方向和主要锚点
- 道具及其状态
- 本段从上一段继承的状态
- 本段结束后必须交给下一段的状态

还应区分不可改变事实和本段允许变化的状态：

```text
Immutable Facts：角色身份、服装关键特征、道具身份、场景布局和世界规则
Mutable States：姿态、表情、道具开关、天气强度、光线、情绪和动作进度
Identity Anchors：最不能丢失的角色与道具识别特征
Continuity Risks：本段最容易发生的身份、空间、状态或方向错误
```

### 7.3 Start Frame 与 End Frame

```text
Start Frame：从上一片段的结束状态自然开始，不重置角色、空间或道具。
End Frame：完成本段目标后的稳定画面，并为下一段保留可接续状态。
Frame Composition：主体、道具和主要空间锚点在画面中的位置。
Motion Vector：片段开始和结束时角色、道具或摄影机的主要运动方向。
Last Stable Pose：片段结束时需要保持的角色、道具和构图状态。
Handoff Hold：结尾需要稳定保持的时间，以及是否保留环境声或 BGM 尾音。
Reference Relationship：下一段是否直接继承本段的尾帧、角色状态或环境状态。
```

结尾建议保留短暂稳定时间，避免视频片段在最后一瞬间突然结束，造成下一段无法接续。

### 7.4 时间轴动作设计

10 秒视频建议拆成 3–5 个主要节拍；15 秒视频建议拆成 4–6 个主要节拍。

```text
0.0–1.5 秒：建立空间和角色状态
1.5–3.5 秒：动作或信息启动
3.5–6.5 秒：主要变化发生
6.5–8.5 秒：反应、后果或升级
8.5–10.0 秒：结果与衔接停留
```

每个时间段只设置一个主要视觉动作，避免把多个连续状态压进一个节拍，造成跳跃、鬼影或子画面。

每个节拍还应标记其电影功能和镜头关系：

```text
Beat Function：SETUP / ACTION / REACTION / CONSEQUENCE / INTERRUPTION / REVEAL / HOLD / HANDOFF
Shot Relation：Continuous Shot / Hard Cut / Match Cut / Dissolve / Time-lapse
Audio Cue：该节拍对应的对白、音效、BGM 或静默变化
Timing Tolerance：允许模型在时间上前后浮动的范围
```

还应控制片段的“事件预算”：10 秒通常只承载一个主要叙事变化和 2–4 个辅助反应；15 秒可以增加停顿、反应和结果展开，但不应无节制增加新的剧情事件。每个节拍都应回答“它改变了什么”，没有改变角色、道具、空间、信息或情绪状态的动作应谨慎保留。

### 7.5 摄影机与画面运动

7.5 是视频提示词的核心模块之一。构图、景别、摄影机、视觉焦点和画面风格共同决定观众如何理解角色表演与事件因果，不能只把它们写成随机镜头类型列表。

视频提示词应同时说明“画面现在如何构成”和“画面将如何变化”。建议至少描述：

```text
Composition：主体、道具、前景、中景、背景、负空间和视觉层级
Shot Size：Establishing / Wide / Medium / Close-up / Insert / Macro 等景别
Framing：画面比例、主体位置、头顶空间、视线空间、运动空间和裁切方式
Camera Height / Angle：摄影机高度、俯仰角、侧向关系和主观/客观视角
Lens Feel：广角、标准、长焦、压缩感、透视感和背景关系
Visual Focus：观众首先看什么，焦点如何从角色转向道具或环境
Movement Path：推、拉、摇、移、跟随、环绕、升降以及运动起止位置
Focus / Depth：焦点转移、景深、背景虚化和前后景关系
Lighting / Color：光线方向、色温、对比度、色彩重点和情绪功能
Shot Purpose：建立空间、强调表演、揭示信息、制造压力、完成反应或交接状态
Transition：从上一镜头如何进入，如何结束并为下一镜头留下什么
```

### 7.5.1 构图设计

构图需要回答以下问题：

- 谁或什么是当前画面的视觉主体
- 角色与道具的相对位置是否体现关系和权力
- 是否需要前景遮挡、框中框、镜面、门窗或其他空间限制
- 负空间是用于孤独、威胁、等待还是视觉呼吸
- 动作方向是否有足够的运动空间和视线空间
- 背景是否提供叙事信息，还是应该被压低以突出表演
- 构图如何从片段开始逐步转向结束构图

构图变化必须服务叙事，例如：

```text
开头使用宽松中景建立父女关系和厨房空间；
录音笔播放时缩小背景并把焦点移到道具；
父亲停止动作后保留一块负空间，强调他的回避；
女儿进入正面视线后重新平衡两人的画面重量；
结尾用稳定双人构图表达关系从对抗转为共同面对。
```

### 7.5.2 景别与镜头功能

景别不是为了覆盖镜头类型，而是为了完成不同的信息任务：

```text
Establishing / Wide：空间关系、人物位置、环境变化
Medium：角色表演、关系和动作过程
Close-up：微表情、视线、犹豫和情绪转折
Insert / Macro：关键道具、手部动作、材质或状态变化
Active Wide：动作重建、空间后果和位置恢复
Final Hold：结果、悬念或下一段的接续锚点
```

同一片段中，景别变化应有明确原因。不能为了“丰富”而随机从远景跳到特写，也不能让连续对白被过度切碎。

### 7.5.3 摄影机运动与画面风格

摄影机运动应独立于角色动作，并说明运动动机：

- 景别和构图
- 摄影机位置
- 推、拉、摇、移或跟随
- 运动速度和结束位置
- 轴线与空间方向
- 不应出现的随机运镜

还应补充：

- 摄影机为什么在此时移动：跟随、观察、揭示、压迫、隔离或重建空间
- 镜头运动是否连续，还是通过剪切完成
- 运动是否会改变观众对角色权力、距离或危险的理解
- 运动模糊、稳定程度和摄影机惯性
- 画面风格如何服务构图：写实、粗粝、梦境、舞台化、压迫、冷静或观察感

7.5 的“画面风格”主要描述镜头级的观看方式；全局材质、色彩和渲染参数仍在 7.10 统一管理，避免两处定义互相冲突。

### 7.6 角色表演与动作

角色部分不应只写“紧张、悲伤、愤怒”等抽象情绪，而应转换为可观察的表演证据。建议至少描述：

```text
Objective：角色此刻想得到什么
Internal Conflict：角色想做什么、又在抗拒什么
Body Performance：姿态、重心、肩颈、手部、动作力度和速度
Face / Eyes：视线、眨眼、微表情、视线回避或停留
Breath：呼吸深浅、节奏、屏息和恢复
Voice：语速、音量、音色、停顿和句尾变化
Reaction：对人物、道具、声音或环境变化的即时反应
Performance Arc：从片段开始到结束，表演发生了什么变化
```

动作描述应包含动机、顺序、速度、力度、反应和结果，而不只是动作名词：

```text
角色先观察，再决定操作；
动作发生后，道具状态必须改变；
角色对变化产生可读反应；
反应应符合前一动作造成的身体和情绪后果；
不要额外添加没有叙事功能的动作。
```

如果存在人物关系或对白，还应补充：

```text
Relationship Dynamic：谁在施压，谁在回避，谁在观察或让步
Subtext：台词表面意思与真实意图
Eye-line：视线对象、方向和变化
Interaction Feedback：一个角色的动作如何改变另一个角色的表演
Lip Sync Priority：是否要求对白与口型高度同步
```

### 7.7 环境状态与物理细节

环境不应只作为静态背景名词出现，而应描述它的状态、变化机制和感官证据：

```text
Environmental State：季节、天气、时间、温度、湿度、光线和空间状态
Material State：地面、墙面、玻璃、金属、布料、植物等材质状态
Physical Response：风、重量、惯性、碰撞、摩擦、液体、烟雾和火花
Visible Evidence：观众能看到的变化，例如水汽、落叶、灰尘、阴影和反光
Audio Evidence：观众能听到的变化，例如风声、回声、雨声和材料摩擦声
Character Impact：环境如何影响角色的动作、服装、呼吸和情绪
```

季节或环境更迭需要细化到可验证的证据。例如不要只写“进入深秋”，而应描述：树叶颜色、落叶数量、地面湿度、光线角度、角色衣物、呼吸可见度、风的强弱和环境声音如何同步变化。

如果一个 10 秒或 15 秒片段要表现跨季节变化，必须明确这是 `Time-lapse / Seasonal Montage`，而不是自然实时连续动作：

```text
春季：湿润泥土、浅绿色新芽、柔和晨光；
夏季：树冠浓密、阳光增强、空气出现热浪；
秋季：叶片变黄、落叶增多、光线变低；
冬季：枝条裸露、地面结霜、环境声音变稀薄。
```

如果没有明确时间压缩，默认不在短片段内突然改变季节，以免破坏连续性。

复杂环境还应区分全局状态与局部状态：

```text
Global State：整个场景的季节、天气、时间和总体光线
Local State：角色附近的水汽、灰尘、破损、光斑、脚印和材质变化
Background Activity：远处人物、动物、车辆、植物或光源是否运动
Weather Continuity：风向、雨势、雪量、雾气和声音是否跨镜头一致
```

### 7.8 道具、状态变化与因果链

道具应记录 `State Before`、触发动作、`State After` 和视觉结果。建议使用：

```text
Action
→ Physical Response
→ Prop State Change
→ Visible Evidence
→ Audio Evidence
→ Character Reaction
```

例如：

```text
角色快速关门
→ 门上的灰尘被震落
→ 门缝光线消失
→ 室内回声变短
→ 角色衣角因惯性继续摆动
→ 角色在黑暗中屏住呼吸
```

这样可以避免环境、道具和动作分别存在，却没有形成因果关系。

如果一个道具依赖其他道具或步骤，还应记录：

```text
Prop Dependency：A 道具完成后，B 道具才能出现或启用
Visibility：关键道具在哪些时间点必须可见
Failure State：操作失败时道具应呈现什么结果
Rollback Check：道具状态不得无原因回退
```

### 7.9 音频、BGM 与音画同步

音频应按轨道、时间轴和混音优先级规划：

```text
Dialogue / Voice：对白、说话人、时间、语气、语言和禁止增加的对白
BGM：类型、速度、乐器、情绪功能、进入、退出、强弱和段落变化
Ambience：环境底噪、空间混响、远处声音和时间状态
Sound Effects：动作、道具、碰撞、机械、脚步和材料声音
Silence：明确需要保留的停顿、无音乐段落或声音突然消失
Mix：对白、音效、环境声和音乐的优先级与压低关系
Audio Continuity：与上一段和下一段的音乐、环境底噪及声音状态衔接
```

BGM 不应只写“配合紧张音乐”，还应说明：

```text
功能：制造压迫感、推动希望、强调转折或保留悬念；
音乐类型：氛围电子、室内乐、打击乐、极简钢琴等；
速度与密度：大致 BPM、节拍密度和声音层数；
配器：低音、弦乐、合成器、打击乐或环境纹理；
动态曲线：进入、增强、停顿、峰值、回落和结束方式；
混音规则：对白出现时 BGM 自动让位，关键音效不能被音乐覆盖；
版权约束：描述音乐方向和声音特征，不默认引用具体受版权保护的歌曲。
```

音频还应标记与画面同步的关键点：

```text
0.0s：保留上一段的环境底噪；
2.3s：道具落地声与画面接触同步；
5.0s：BGM 短暂停止，突出角色吸气；
8.5s：主要结果出现，加入低频音效；
9.0–10.0s：保留尾音和环境声，为下一段衔接。
```

还应区分声音是否来自画面内，以及声音的空间视角：

```text
Diegetic Sound：画面内可找到声源的声音，例如脚步、广播、收音机和机械声
Non-diegetic Sound：画外音乐、情绪音色和非现实声音
Sound Perspective：声音来自近处、远处、墙后、设备内部或角色主观听觉
```

如果目标视频模型无法原生生成音频，视频提示词仍保留完整音频设计，但应标记为后期混音输入，不让模型通过画面动作强行伪造对白或 BGM。

### 7.10 视觉风格与执行参数

除总体风格外，还可以补充模型执行所需的视觉信息：

- 光线方向、色温和对比度
- 镜头焦段感、景深和运动模糊
- 材质表现和颗粒质感
- 画面清晰度与运动强度
- 现实主义、动画化或风格化程度
- 需要保持不变的角色和道具识别特征

这些信息应服务于故事、动作和连续性，不能用大量风格词掩盖缺少事件逻辑的问题。

还可以补充：

- 色彩脚本和跨单元色彩连续性
- 光线方向与阴影连续性
- 角色肤色、服装色和关键道具颜色的稳定性
- 参考图之间发生冲突时的优先级
- 运动模糊、颗粒和画面纹理是否跨段保持一致

### 7.11 提示词优先级与执行层级

长提示词中应区分不同约束的优先级：

```text
MUST：角色身份、关键道具、时间顺序、起止状态、对白和硬性禁止项
SHOULD：摄影机节奏、表演细节、环境物理、BGM 情绪和材质表现
MAY：可替代的镜头修饰、次要环境细节和风格化偏好
AVOID：额外剧情、额外对白、身份变化、道具回滚、随机转场和无功能动作
```

推荐先分析故事板，再写不可改变的事实和时间轴动作，最后写风格修饰与可选细节，避免模型跳过故事板而仅凭剧本重新发明画面。

在故事板驱动的视频任务中，推荐采用以下输入优先级：

```text
用户明确硬约束
→ 故事板视觉结构与 Panel 顺序
→ Continuity In / Continuity Out
→ 分段剧本与故事目标
→ 音频设计
→ 环境物理补充
→ 风格修饰与模型推断
```

故事板优先意味着：

- 故事板中的构图、景别、角色相对位置、道具状态和镜头顺序默认必须保留
- 视频提示词主要负责把静态 Panel 之间的关系转化为连续运动、表演、摄影机变化和音频
- 分段剧本用于解释动机、潜台词和因果，不应无故覆盖故事板已经明确的视觉事实
- 音频设计用于补充对白、BGM、环境声和音效，不应反向改变故事板中的视觉事件
- 如果故事板与剧本或其他素材发生冲突，Agent 应记录冲突；只有用户明确要求修改故事板时，才允许覆盖其视觉事实

### 7.11.1 最终视频提示词中的故事板核心指令

除了 Agent 内部按照故事板优先级进行分析外，最终交给视频模型的提示词正文中，也必须明确写出故事板的使用方式。不能只在内部处理，而让视频模型自行猜测参考图的作用。

建议在最终视频提示词开头加入类似以下的固定指令：

```text
以提供的故事板图片作为本段视频的核心视觉素材进行分析并生成视频。
请按照故事板中的 Panel 顺序、构图、景别、角色姿态、角色相对位置、道具状态、空间关系和镜头变化，将静态分镜转化为连续的表演、动作、摄影机运动和环境变化。
保留故事板已经确定的视觉事实，不要重新设计场景、角色、构图或事件顺序；只在故事板明确的基础上补充合理的运动、表演、物理反应和音频。
故事板上的箭头、图标、Panel 序号、网格边框、标签、摄影机标记、色彩注释、技术文字和说明文字仅用于分析，不得出现在正式视频画面或音频中。
只有当某个标记明确代表场景内真实存在的物体、屏幕内容或环境文字时，才可以将其作为剧情元素保留，并必须按真实场景中的方式呈现。
如果故事板与后续文字描述存在冲突，优先保留故事板中的视觉结构，并将文字理解为对运动、动机、声音和连续性的补充。
```

这条指令的作用是把“故事板是核心素材”直接传递给视频模型。后续的时间轴、角色表演、摄影机、环境、音频和负面约束，都应围绕故事板进行展开，而不是另起炉灶重新生成一套画面。

当不同要求发生冲突时，建议采用以下顺序：

```text
硬连续性事实
→ 片段叙事目标
→ 时间轴动作
→ 角色表演
→ 构图与摄影机
→ 环境物理
→ 音频
→ 风格修饰
```

例如，风格要求不能覆盖角色身份；摄影机运动不能破坏单一动作；BGM 不能覆盖对白和关键音效。

### 7.12 风格与负面约束

风格描述需要与动作、音频和连续性分开；负面约束则集中说明：

- 不要改变角色身份、年龄、服装或关键外观特征
- 不要让道具消失、换位、无原因回滚或改变材质
- 不要添加额外对白、字幕、Logo、水印或错误文字
- 不要把故事板箭头、图标、Panel 序号、网格边框、标签、摄影机标记、色彩注释、技术文字或说明文字渲染进正式视频
- 不要产生 ghost pose、onion-skin、残影、子画面或不合逻辑的肢体
- 不要把 Dialogue、Horror 或 Procedural Montage 错误生成成 Action 打斗
- 不要让 BGM 覆盖对白、关键音效或有功能的静默
- 不要加入没有叙事功能的随机镜头运动、粒子、闪光或环境变化

故事板上的辅助标注必须被视为“分析层”，而不是“成片层”：Agent 可以读取它们来理解动作方向、镜头关系、Panel 顺序和构图意图，但最终视频默认只呈现场景内的角色、道具、环境、摄影机运动和声音。

负面约束可分为四类，并优先保留当前片段最可能发生的 5–12 个问题：

```text
Continuity Errors：变脸、换装、道具消失、空间跳变、状态回滚
Motion Errors：鬼影、残影、重复肢体、无惯性、动作顺序错乱
Visual Errors：字幕、Logo、水印、错误文字、随机闪光和无功能粒子
Audio Errors：额外对白、口型不同步、BGM 覆盖对白、声音突然断裂
```

### 7.13 生成前自检与预期结果

在发送最终视频提示词前，Agent 应快速确认：

```text
Start Frame 能否接上上一段？
End Frame 能否交给下一段？
视频提示词是否真正以故事板为核心素材进行分析？
最终视频提示词正文是否明确写出“以故事板图片为核心素材进行分析并生成视频”？
Panel 顺序、构图、景别、角色姿态和道具状态是否被保留？
时间轴是否超过本片段的事件承载能力？
每个节拍是否只有一个主要变化？
角色表演是否有可观察证据？
构图、景别和镜头运动是否服务叙事？
道具和环境是否存在明确因果链？
环境变化是否有视觉和声音证据？
BGM 是否会覆盖对白、关键音效或静默？
负面约束是否针对当前片段，而不是无差别堆叠？
```

预期结果不是让模型机械复述所有字段，而是让生成的视频在起止状态、动作因果、表演、构图、声音和连续性上都可被检查。

## 8. 音频提示词与视频提示词的关系

推荐保留两个层级：

```text
Audio Design（音频设计，独立来源）
        ↓
Final Video Prompt 的 Audio Section（整合后的音频区块）
```

这样既能单独审查音频设计，也能保证最终发送给视频模型的提示词包含完整音频要求。

不建议手动维护两份彼此独立、可能发生分歧的音频长文本。

## 9. 10 秒与 15 秒片段的关系

10 秒和 15 秒使用同一套故事板单元结构，只改变时长和节奏分配。

15 秒不应该简单等于“10 秒内容再增加几个事件”。更好的方式是增加：

- 空间建立时间
- 角色反应时间
- 动作完成后的余韵
- 镜头停留
- 音频过渡

也就是说：

```text
10 秒：同一事件的紧凑版本
15 秒：同一事件的更完整、更有呼吸感版本
```

15 秒片段生成速度较慢，因此默认仍使用 10 秒；只有当叙事需要更完整的动作、停顿或情绪展开时才选择 15 秒。

## 11. 已达成的共识

1. 长视频应拆分成多个故事板单元，而不是只生成一张总故事板。
2. 默认每个单元为 10 秒，也支持 15 秒。
3. 一个故事板单元对应一个完整的视频片段和一个完整的视频提示词。
4. 每个单元需要有分段剧本或段落简介，但不重复完整总剧本。
5. 视频提示词必须同时包含画面、动作、镜头、连续性、角色表演、环境物理和音频内容。
6. 音频应有独立的音频设计，并整合进最终视频提示词的 Audio Section；BGM 需要描述功能、速度、配器、动态曲线和混音关系。
7. 相邻单元默认通过 Continuity Handoff 衔接，不默认增加独立过渡故事板。
8. 每个单元必须显式记录 `Continuity In` 和 `Continuity Out`。
9. 视频提示词应使用带时间轴、镜头结构和区块优先级的结构化长提示词，而不是无结构的长段落；Generation Mode 不写死，由 Agent 根据输入和上下文自适应判断。
10. 故事板是基于故事板生成视频时的核心视觉素材；Agent 必须先分析故事板，再将 Panel 关系转译为连续运动、表演、摄影机和音频。
11. 最终视频提示词正文必须明确写出“以提供的故事板图片为核心素材进行分析并生成视频”，不能只依赖 Agent 的内部判断。
12. 故事板上的箭头、图标、Panel 序号、边框、标签、摄影机标记、色彩注释和技术文字属于分析层，默认不得出现在正式视频画面或音频中。
13. 角色表演应从目标、内心冲突、身体姿态、视线、呼吸、声音和即时反应等可观察证据描述。
14. 构图、景别、镜头、视觉焦点、摄影机运动和镜头级画面风格与角色表演同等重要，必须有明确的叙事功能。
15. 环境应描述季节、天气、时间、材质、物理反应、可见证据、声音证据、背景活动以及对角色的影响。
16. 道具和环境变化应尽量形成“动作 → 物理响应 → 状态变化 → 视觉/声音证据 → 角色反应”的因果链。
17. 跨季节或大尺度环境变化必须明确使用时间压缩或蒙太奇；普通短片段默认保持自然连续性。
18. 10 秒和 15 秒片段都要控制事件预算；15 秒优先增加停顿、反应、余韵和衔接，不简单增加剧情事件。
19. 负面约束不仅限制画面错误，也应限制额外对白、随机运镜、无功能粒子、BGM 覆盖对白和破坏性环境变化，并按错误类型分类。
20. 生成前需要检查故事板是否被完整分析和保留，以及起止状态、时间轴、角色表演、构图、镜头、道具因果、环境证据、音画同步和负面约束。

## 12. 暂不决定的事项

以下问题尚未进入实现决策：

- 主要使用首帧图生视频，还是纯文本生成视频
- 是否需要同时提供首帧、尾帧或中间参考帧
- 视频模型对 10 秒、15 秒提示词长度和音频控制的具体限制
- 一个故事板单元内部是否需要进一步定义镜头节拍对象
- 音频是由视频模型一并生成，还是独立生成后混音
- `Storyboard Unit` 最终采用单文件还是多个关联文件
- 是否需要为每个单元生成结构化 JSON 或其他中间数据
- 是否需要增加跨单元连续性 Validator

这些事项应在明确目标视频模型和实际生成工作流后再决定。
